# zeta-common/src/main/java/hu/blackbelt/judo/zeta/common — agent notes

Shared runtime between `validation-core` and `transformation-core`: the metamodel plug-in seam (`ModelProvider`), the `@ExtensionMethod` dispatch registry, and the `@Cached` key machinery. This package deliberately does NOT compile against `zeta-annotations` — annotations are matched by simple name via reflection to keep the two modules acyclic.

| File | Purpose |
|---|---|
| `CacheKey.java` | Immutable composite key for `@Cached` extension-method results and `satisfies()` verdicts. Exports ctor `CacheKey(List<Object> parts)`, `equals`, `hashCode`, `toString`. `final` class; `parts` defensively copied via `List.copyOf` and `hashCode` precomputed in the ctor — a part mutated after construction makes the cached `hashCode` stale and the entry unfindable, so parts must be value-like. Build instances through `CacheKeyBuilder`, not by hand. |
| `CacheKeyBuilder.java` | Turns a method invocation into a stable `CacheKey` using per-type strategies. Exports `build(Object self, String methodName, Object... args)` and `buildSatisfiesKey(EObject element, String constraintName)` (literal `"satisfies"` discriminator part). Key parts: `EObject` → XMI id from `XMIResource.getID`, falling back to `EcoreUtil.getURI().toString()` then `System.identityHashCode`; `String`/`Number`/`Boolean`/`Enum` → value; `Collection` → ordered part list, so reordering changes the key; `Map` → entries sorted by `String.valueOf(key)`; `null` → private `NULL_MARKER`. Anything else falls back to `System.identityHashCode`, which is per-instance and defeats caching across equal-but-distinct objects. All members static. |
| `ExtensionMethodDescriptor.java` | Reflective handle on one registered `@ExtensionMethod` method plus its cached flag. Exports ctor `(Object instance, Method method, boolean cached)`, `getName()`, `isCached()`, `getParameterTypes()`, `invoke(EObject target, Object... args)`, `matchesArguments(Object... args)`. Ctor calls `method.setAccessible(true)`. `invoke` prepends `target` as parameter 0 (the `self` slot) and wraps any failure in `RuntimeException` — the original `InvocationTargetException` is the cause, not the thrown type. `matchesArguments` requires `paramTypes.length == args.length + 1`, skips slot 0, and rejects a `null` argument against a primitive parameter. |
| `ExtensionMethodRegistry.java` | Registers `@ExtensionMethod` classes and dispatches `@Cached`-aware calls into them at rule-body time. Exports `register(Class<?>)`, `<T> T invoke(EObject target, String methodName, Object... args)`, `clearCache()`, `getExtensionsFor(Class<? extends EObject>)`. `register` requires the `@ExtensionMethod` annotation (else `IllegalArgumentException`), instantiates the class through its no-arg declared constructor, and registers only `public` declared methods. Annotations are matched by SIMPLE NAME (`"ExtensionMethod"`, `"Cached"`) precisely to avoid a zeta-common → zeta-annotations dependency — renaming either annotation silently disables discovery. Lookup walks the full class-and-interface hierarchy of the target (`LinkedHashSet` order), so an EMF interface registration matches its impl; no match throws `IllegalArgumentException`. Cached results live in a `ConcurrentHashMap<CacheKey, Optional<Object>>` — `Optional` is what lets a `null` return be cached. `extensions` map is a plain `HashMap`, so `register` is not thread-safe; register before executing. Cache survives until `clearCache()`, which the executors call at end of run. |
| `ModelProvider.java` | The interface a metamodel implements to plug itself into Zeta — the one seam keeping the engine free of metamodel dependencies. Exports abstract `<T extends EObject> Collection<T> getAllContents(ResourceSet, Class<T>)` plus `default String getName(EObject)` and `default String getTypeName(EObject)`. Implementations delegate `getAllContents` to their own utils (`AsmModelProvider` → `AsmUtils.all(type)`). Default `getName` reflectively calls `getName()` and swallows any failure to `null`; default `getTypeName` returns `element.eClass().getName()`. Both defaults feed validation-message interpolation only, so a `null` name degrades a message rather than failing a run. |
