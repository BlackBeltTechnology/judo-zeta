# validation-core/src/test/java/hu/blackbelt/judo/zeta/validation — agent notes

Shared test fixtures for the validation framework. Tests validate Zeta against the ECore metamodel itself (`EClass`, `EPackage`, `EAttribute`) — no JUDO metamodel is on the test classpath, which is deliberate: it proves the engine is metamodel-agnostic.

| File | Purpose |
|---|---|
| `AbstractValidationTest.java` | JUnit 5 base class wiring a fresh validation stack per test. Exposes `protected` fields `resourceSet`, `testResource`, `registry`, `extensionRegistry`, `context`, plus `setUp()` (`@BeforeEach`), `tearDown()` (`@AfterEach`), `addToModel(T element)` returning the element for fluent use. `setUp` builds a `ResourceSetImpl`, maps protocol `"test"` to `XMIResourceFactoryImpl`, creates `test://test-model`, and constructs `ValidationContext(new TestModelProvider(), resourceSet, extensionRegistry)` then calls `setValidationRegistry(registry)` — a subclass that skips `super.setUp()` gets a context whose `satisfies()` silently returns true. `@TestInstance(Lifecycle.PER_METHOD)`, and `tearDown` clears resources and nulls every field, so no state crosses tests. Elements NOT passed through `addToModel` are invisible to `context.all(...)` and never validated. |
| `TestModelFactory.java` | Builds ECore instances for validation fixtures without an `.ecore` file. Exports static `createEClass(String)`, `createEAttribute(String, EDataType)`, `createEPackage(String name, String nsURI)`, `createEReference(String, EClass type)`, `createEOperation(String)`, `createSimpleTestModel()`, and the `EcorePackage` datatype shortcuts `getEString()`, `getEInt()`, `getEBoolean()`. All static. Created elements are detached — they belong to no `Resource` until `AbstractValidationTest.addToModel(...)` adds them, so a fixture built here and never added yields zero validation results. `createSimpleTestModel()` returns a populated `EPackage` for tests that want a whole tree rather than single elements. |
| `TestModelProvider.java` | Minimal `ModelProvider` implementation letting the engine traverse a plain ECore `ResourceSet`, standing in for `AsmModelProvider` et al. Exports `getAllContents(ResourceSet, Class<T>)`. Iterates every `Resource` in the set with `resource.getAllContents()` (which DOES include root elements) and filters by `type.isInstance` — subtype-inclusive, not exact-type. Inherits `ModelProvider`'s default `getName`/`getTypeName`, so message interpolation goes through the reflective `getName()` path. Returns a fresh `ArrayList` each call; no caching, so cost is O(model) per rule type. |
| `TestValidators.java` | Catalogue of annotated rule classes covering every validation annotation, used as fixtures across the `core/` and `integration/` tests. Exports nested `@ValidationContext` classes `EClassValidator` (`eClassMustHaveName` `@Constraint`, `eClassShouldStartWithCapital` `@Critique`), `EPackageValidator` (`ePackageMustHaveNsURI`), `AlwaysPassValidator`/`AlwaysFailValidator`/`EClassAlwaysFailValidator` (deterministic outcomes), `GuardedValidator` (`guardedConstraint` + `isAbstract` guard), `CountingValidator`/`EClassCountingValidator` (count executions to assert caching and skip behaviour), `HookValidator` (`preHook` `@PreExecution`, `postHook` `@PostExecution`, `hookConstraint`), `DependentValidator` (`baseConstraint` + `dependentConstraint` with `@Satisfies`), plus `@ExtensionMethod` classes `EClassExtensions` (`getNameUpper`, `cachedGetName` `@Cached`, `nonCachedGetName`, `getAttributeCount`) and `InvalidExtensions` (`someMethod`, deliberately missing `@ExtensionMethod` so registration failure can be asserted). Each class needs a public no-arg constructor or `ValidationRegistry.register` throws. The counting validators hold mutable per-instance counters — the registry instantiates once at register time, so a counter is shared across the whole run and must be reset per test. |
