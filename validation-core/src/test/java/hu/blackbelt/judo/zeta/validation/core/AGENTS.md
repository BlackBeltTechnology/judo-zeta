# validation-core/src/test/java/hu/blackbelt/judo/zeta/validation/core — agent notes

Unit tests for the validation engine. All but `ValidationResultTest` extend `AbstractValidationTest` (`../AbstractValidationTest.java`) and use the fixtures in `../TestValidators.java` / `../TestModelFactory.java`. JUnit 5 with `@Nested` groups + `@DisplayName`; classes are package-private.

| File | Purpose |
|---|---|
| `AnnotationProcessingTest.java` | Proves each Zeta annotation is honoured end to end, one `@Nested` group per annotation: `@Constraint` (name/message captured, rule runs), `@Critique` (registers as `WARNING`), `@Guard` (skips on false, runs on true), `@Satisfies` (dependent rule skipped when prerequisite fails, runs when it passes), `@PreExecution`/`@PostExecution` (hooks fire before/after), `@ExtensionMethod` (class registers, `ctx.call` dispatches), `@Cached` (result reused vs. non-cached method recomputed), `@ValidationContext` (type binding, rules apply only to matching context types). Extends `AbstractValidationTest`. This is the regression net for the annotation contract — changing an annotation's retention, target, or element name breaks here first. |
| `ExtensionMethodRegistryTest.java` | Covers `ExtensionMethodRegistry` registration, dispatch, caching and hierarchy lookup. `@Nested` groups: registration (annotated class registers; class WITHOUT `@ExtensionMethod` throws), invocation (dispatch, computed result, NULL return handled — the `Optional` wrapping — and missing method throws), caching (`@Cached` reuses, non-cached recomputes, `clearCache()` works, cache is keyed PER ELEMENT), type hierarchy (exact type match, `getExtensionsFor` returns the registered type's methods). Extends `AbstractValidationTest`. The per-element caching case is the one that pins `CacheKeyBuilder`'s XMI-id keying. |
| `ValidationContextTest.java` | Covers `ValidationContext` state and query surface. `@Nested` groups: current element (get/set/clear, null when unset, and an explicit THREAD-LOCAL isolation test — that test is what pins `currentElement` as `ThreadLocal`), satisfies cache (pass/fail evaluation, results memoised, `clearSatisfiesCache()`, per-element evaluation, and the contract that an UNKNOWN constraint name returns `true`), `allSatisfy` (all-pass vs. any-fail), `getAllInstances` (finds instances, empty when none, exact-type filtering), extension-method invocation (via context, on current element, `clearExtensionCache()`), attributes (set/get, null for missing, overwrite), accessors, and resource aliases (`"source"` registered by default, custom alias register/retrieve/overwrite, unknown alias throws). Extends `AbstractValidationTest`. |
| `ValidationExecutorTest.java` | Covers `ValidationExecutor` run mechanics: sequential validation, failures returned, PASSING results filtered out, empty collection handled, parallel path exercised, `shutdown()`, pre/post hook invocation, caches cleared after a run, all applicable validators executed, and mixed element types dispatched correctly. Flat `@Test` methods, no `@Nested`. Extends `AbstractValidationTest`. Note the parallel test does not reach `PARALLEL_THRESHOLD` (5000) with realistic fixtures — it constructs the executor with `parallel = true` and asserts behaviour parity, not thread count. |
| `ValidationRegistryTest.java` | Covers `ValidationRegistry` registration and lookup. `@Nested` groups: registration (single class, multiple classes, and a class WITHOUT `@ValidationContext` which must WARN and be skipped, not throw), lookup (exact type, supertype, multi-level inheritance, `getValidatorByName` incl. null for an unknown name, `getAllValidators`), hooks (pre, post, and multiple hooks across multiple validator classes), and descriptor metadata (`@Constraint` → `ERROR`, `@Critique` → `WARNING`). Extends `AbstractValidationTest`. The skip-on-missing-annotation case pins the silent-warn behaviour deliberately. |
| `ValidationResultTest.java` | Pure value-object test of `ValidationResult` — the ONLY file here that does NOT extend `AbstractValidationTest`, since no EMF model or registry is needed. `@Nested` groups: creation (pass, fail with message, fail with full metadata, warn, warn with full metadata), state (`isPassed`/`isFailed` complementary), severity (`ERROR` for fail, `WARNING` for warn, NULL for pass), message verification (exact error/warning text, dynamic content), and `equals`/`hashCode` (equal results equal, hash consistent, different results unequal). |
| `ValidatorDescriptorTest.java` | Covers `ValidatorDescriptor` matching, metadata, lazy loading and evaluation. `@Nested` groups: `appliesTo` (matching type true, non-matching false, SUBTYPE true when registered for the supertype — validation matching is `isInstance`, unlike transformation's default type-of), metadata (name, message, `ERROR` vs `WARNING`, context type), rule loading (rule fetched lazily on first `getRule()` and the instance CACHED thereafter), guard evaluation (null guard when none declared, guard returned when declared, false for non-abstract / true for abstract via `TestValidators.GuardedValidator.isAbstract`), validation execution (pass, fail, skip-on-guard-false, run-on-guard-true), `@Satisfies` dependencies (empty list by default, dependencies exposed, dependent skipped/executed by prerequisite outcome), and `toString`. Extends `AbstractValidationTest`. |
