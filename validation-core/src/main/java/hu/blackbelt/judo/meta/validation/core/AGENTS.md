# validation-core/src/main/java/hu/blackbelt/judo/meta/validation/core — agent notes

The Java-native EVL replacement. Directory path says `meta/validation/core` but every file declares package `hu.blackbelt.judo.zeta.validation.core` — the source layout does NOT mirror the package, so IDE "move to matching folder" refactors break the build.

Runtime shape: `ValidationRegistry.register(RuleClass)` reflects `@ValidationContext`/`@Constraint`/`@Critique`/`@Guard`/`@Satisfies` into `ValidatorDescriptor`s; `ValidationExecutor.validate()` walks the elements a `ModelProvider` yields and returns only the FAILED `ValidationResult`s.

| File | Purpose |
|---|---|
| `Guard.java` | `@FunctionalInterface` for a rule short-circuit predicate. Exports `boolean evaluate(EObject element, ValidationContext ctx)`. `false` skips the rule and the executor reports `ValidationResult.pass()` — a guard cannot itself fail a rule. `ValidatorDescriptor.getGuard()` adapts a `@Guard(method=…)` reflective method into this shape, so the annotated method must have exactly the `(EObject, ValidationContext)` signature. |
| `Severity.java` | Two-constant enum classifying a failure. Exports `ERROR` (emitted for `@Constraint`, blocks model processing) and `WARNING` (emitted for `@Critique`, advisory). No `INFO`/`FATAL` level exists — consumers splitting results by severity handle exactly these two. |
| `ValidationContext.java` | Per-run state handed to every rule body: model access, alias registry, `satisfies()` memoisation, extension-method dispatch, user attributes. Exports ctor `(ModelProvider, ResourceSet, ExtensionMethodRegistry)`, `setValidationRegistry`, `getModelProvider`, `getResourceSet`, `getCurrentElement`/`setCurrentElement`/`clearCurrentElement`, `satisfies(String)`, `satisfies(EObject, String)`, `allSatisfy(Collection, String)`, `getAllInstances(Class)`, `registerResource(String, ResourceSet)`, `getResource(String)`, `all(String alias, Class)`, `call(EObject, String, Object...)`, `call(String, Object...)`, `setAttribute`/`getAttribute`, `clearSatisfiesCache`, `clearExtensionCache`. Ctor pre-registers the ctor `ResourceSet` under alias `"source"`; `registerResource` rejects a null alias or ResourceSet with `IllegalArgumentException`, and `getResource` on an unknown alias throws listing the known ones. `currentElement` is a `ThreadLocal` — the no-arg `satisfies`/`call` overloads only work on the thread the executor set it on, and parallel chunks must not share it. `satisfies` uses a private identity-based `CacheKey` (`element ==`, not `equals`) and an `EVALUATING` state that returns `true` on re-entry, so a cyclic `@Satisfies` chain terminates optimistically instead of overflowing the stack. `evaluateConstraint` returns `true` when no `ValidationRegistry` was set or no rule of that name applies — an unknown constraint name is silently satisfied, never an error. `setAttribute` wraps in `Optional` so a null value is storable. |
| `ValidationExecutor.java` | Drives a validation run: collects elements, dispatches descriptors, returns failures. Exports ctor `(ValidationRegistry, ValidationContext, boolean parallel)`, `validate()`, `validate(Collection<? extends EObject>)`, `shutdown()`. `validate()` builds the element set from each descriptor's `getResourceAlias()` + `getContextType()` via `context.all(...)` into a `LinkedHashSet`, so an element matched by two rules is validated once. Returns ONLY results where `isFailed()` — passing rules produce nothing. Parallelism engages only when `parallel == true` AND `elements.size() >= PARALLEL_THRESHOLD` (5000); chunk size is `max(100, ceil(size / availableProcessors))` over an `Executors.newWorkStealingPool()` created lazily under double-checked locking on a `volatile` field. Rule bodies therefore run on pool threads and must be thread-safe. `invokePreValidationHooks` / `invokePostValidationHooks` bracket the run in a `try/finally`, which also clears the satisfies and extension caches — so results are not memoised across `validate` calls. `isFromExpectedAlias` filters an element out unless its owning `ResourceSet` equals the alias's, falling back to `"source"` when the element has no resource. `shutdown()` must be called or the work-stealing pool leaks; it waits 60 s then `shutdownNow()` and re-sets the interrupt flag. |
| `ValidationRegistry.java` | Reflects annotated rule classes into descriptors and owns the type→descriptor index. Exports `register(Class<?>)`, `getValidatorsFor(Class<? extends EObject>)`, `getValidatorByName(String)`, `getAllValidators()`, `invokePreValidationHooks(ValidationContext)`, `invokePostValidationHooks(ValidationContext)`. `register` WARNS and returns silently when the class lacks `@ValidationContext` — a mis-annotated rule class contributes nothing and does not fail; it instantiates via the no-arg declared constructor and scans declared methods for `@Constraint` (→ `Severity.ERROR`), `@Critique` (→ `Severity.WARNING`), `@PreExecution`, `@PostExecution`. A `@Guard` whose named method is missing the exact `(EObject, ValidationContext)` signature throws `RuntimeException` at registration. `descriptorsByName` is keyed by rule `name()`, so two rules sharing a name silently overwrite each other for `getValidatorByName` and `satisfies` lookup. `getValidatorsFor` unions rules registered on the class, its `EObject`-assignable superclass chain, and all interfaces recursively — an interface-registered rule fires for the EMF impl class. Backing maps are plain `HashMap`; `register` before executing, never concurrently. Hook invocation catches and LOGS exceptions rather than propagating — a broken `@PreExecution` does not fail the run. |
| `ValidationResult.java` | Immutable verdict of one rule against one element. Exports factories `pass()`, `fail(String message)`, `fail(String constraintName, String message, Severity, EObject context)`, `warn(String message)`, `warn(String constraintName, String message, EObject context)`, plus `isPassed`, `isFailed`, `getConstraintName`, `getMessage`, `getSeverity`, `getContext`, `equals`, `hashCode`, `toString`. `final` class, private ctor — construct only through the factories. `pass()` carries null name/message/severity/context, so `getSeverity()` is null on a pass. Single-arg `fail` defaults to `Severity.ERROR` and single-arg `warn` to `Severity.WARNING`, both with a null `constraintName` — that null is the signal `ValidatorDescriptor.validate` uses to substitute the rule name and interpolated message. |
| `ValidationRule.java` | `@FunctionalInterface` every `@Constraint`/`@Critique` method must return. Exports `ValidationResult validate(EObject element, ValidationContext ctx)` and static `builder()` → `ValidationRuleBuilder`. The annotated method returns this lambda; it does NOT itself validate, and `ValidatorDescriptor.getRule()` invokes the method once and caches the lambda, so the method must be side-effect-free and cheap. |
| `ValidationRuleBuilder.java` | Fluent assembly of a `ValidationRule` from guards plus a check function. Exports `guard(Guard)`, `and(Guard)` (alias for `guard`), `check(BiFunction<EObject, ValidationContext, ValidationResult>)`, `build()`. Guards compose with AND and are evaluated before the check; ANY failing guard short-circuits to `ValidationResult.pass()`, so a guarded-out element is indistinguishable from a passing one. `build()` throws `IllegalStateException("Validation check must be set")` when `check` was never supplied. `check` is single-valued — a second `check(...)` replaces the first, while `guard(...)` accumulates. |
| `ValidatorDescriptor.java` | Registry's runtime record of one rule: identity, severity, context type, guard, `@Satisfies` deps, resource alias, plus the evaluation entry point. Exports two ctors (8-arg defaulting `resourceAlias` to `"source"`, and the 9-arg full form), `getName`, `getMessage`, `getSeverity`, `getContextType`, `getSatisfiesDependencies`, `getResourceAlias`, `getRule`, `getGuard`, `appliesTo(EObject)`, `validate(EObject, ValidationContext)`, `toString`. Ctor calls `setAccessible(true)` on the rule and guard methods and coerces a null `resourceAlias` to `"source"`. `getRule()` and `getGuard()` memoise into non-volatile `cachedRule`/`cachedGuard` — benign under the executor's write-once pattern but not a safe publication guarantee. `validate` short-circuits to `pass()` when any `@Satisfies` dependency is unsatisfied or the guard returns false, so a skipped rule reports as passing. When the rule returns a failure with a null `constraintName`, the descriptor re-wraps it with its own `name`, `severity`, `element` and the interpolated `message`. Interpolation supports exactly one token, `{element.name}`, resolved by reflectively calling `getName()`; failure is swallowed and the token is left in the message verbatim. `appliesTo` is `contextType.isInstance(element)` — subtype-inclusive, unlike transformation's default type-of matching. |
