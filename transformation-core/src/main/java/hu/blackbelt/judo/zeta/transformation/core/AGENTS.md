# transformation-core/src/main/java/hu/blackbelt/judo/zeta/transformation/core — agent notes

The Java-native ETL replacement. `TransformationRegistry.register(RuleClass)` reflects `@TransformationContext`/`@TransformRule`/`@Transform`/`@To`/`@Lazy`/`@Greedy`/`@Extends`/`@Guard` into `TransformRuleDescriptor`s; `TransformationExecutor.transform()` runs eager rules, then lazy rules on demand via `TransformationContext.equivalent(...)`, resolving through `ElementResolutionCache` and recording links in `TransformationTrace`.

Two dimensions of ETL compatibility live here and are easy to confuse: `ExecutionStrategy` (loop nesting) and `EquivalentDiscriminatedStrategy` (clone semantics). Neither implies the other.

| File | Purpose |
|---|---|
| `ActivationTracker.java` | Records which source elements an `equivalent()` call has activated per `@ActivityBased` rule, so phase 2 processes only those. Exports `activate(String ruleName, EObject source)`, `getActivated(String)`, `hasActivations(String)`, `getRulesWithActivations()`, `getTotalActivationCount()`, `clear()`, `toString()`. Backed by `ConcurrentHashMap<String, Set<EObject>>` with `newKeySet()` values — safe to call from parallel rule bodies. `activate` silently no-ops on a null rule name or source instead of throwing. `getActivated` returns an EMPTY set for an unknown rule and an unmodifiable view otherwise; the view still reflects later `activate` calls. Elements dedupe by `EObject` `equals`/`hashCode`. |
| `DiscriminatorResolver.java` | `@FunctionalInterface` hook letting a transformation compute the discriminator for `equivalentDiscriminated()` from the current rule call chain, plus choose the cache mode. Exports nested `record Resolution(String discriminator, boolean useDiscriminatorOnlyCache)` with factories `sourceBasedCache(String)` and `discriminatorOnlyCache(String)`, `default Resolution resolve(EObject source, String ruleName, List<RuleInvocation> callChain)`, and the abstract `@Deprecated String resolveDiscriminator(...)`. Invoked ONLY when `equivalentDiscriminated` is called with a null explicit discriminator; returning null falls back to default behaviour. `sourceBasedCache` keys on `(source, ruleName, discriminator)`; `discriminatorOnlyCache` keys on `(ruleName, discriminator)` alone, so distinct sources SHARE one target instance — that is the ETL string-cache semantics (shared `ActionDefinition` across Button/Action contexts) and the mode that makes cross-source mutation visible. The default `resolve` delegates to the deprecated `resolveDiscriminator` and always picks source-based caching; override `resolve` to get discriminator-only mode. Install via `TransformationContext.setDiscriminatorResolver(...)`. |
| `ElementResolutionCache.java` | The transformation trace and `equivalent()` resolution store: source→target mappings, discriminated variants, rejection memo, in-progress markers, and per-key locks. Exports ctors (default = parallel mode, `(boolean sequential)`), nested `TraceEntry` (`getSource`, `getTarget`, `getRuleName`, `getDiscriminator`, `isPrimary`), `isSequentialMode`, `getLockFor`/`lock`/`unlock`/`tryLock`/`lockInterruptibly`, `markInProgress`/`getInProgress`/`clearInProgress`/`hasAnyInProgress`, `addMapping`, `addDiscriminatedMapping`, `getByRule`, `getOrCreate`, `getEquivalent`, `getEquivalents`, `getEquivalentDiscriminated`, `getAllMappings`, `findByName`, `unwrapAllProxies`, `clear`, `clearRejections`, `clearInProgressTracking`. Cache key is `(source element, rule name)` and DELIBERATELY excludes the calling rule — that is what makes transformation idempotent and XMI ids the flat `(source_id)/RuleName` form, versus ETL's context-keyed cache which yields compound ids and multiple targets per pair. Do not "fix" this to match ETL. In sequential mode all locking is bypassed and the backing maps are `IdentityHashMap`s, so a cache constructed sequential must never be driven from more than one thread; switch modes through `TransformationContext.configureSequentialMode`, which rebuilds the cache and DISCARDS existing mappings on an actual mode change. In-progress markers are indexed by rule ordinal, so a descriptor without an assigned ordinal cannot participate in circular-dependency resolution. Rejected `(source, rule)` pairs are memoised so a failing guard is evaluated once — `clearRejections()` is required after mutating anything a guard reads. |
| `EquivalentDiscriminatedStrategy.java` | Two-constant enum picking the clone semantics of `equivalentDiscriminated()`. Exports `CLONE_PRISTINE` (Zeta default — every caller gets a clone of the pristine original, mutations isolated per clone) and `CLONE_CURRENT_STATE` (ETL's `id.eol` semantics — the FIRST caller gets the original object itself, later callers clone its current possibly-mutated state, so first-caller mutations propagate). `CLONE_CURRENT_STATE` depends on mutation ordering and therefore REQUIRES sequential execution; combining it with deferred writes throws `IllegalStateException`. Set via `TransformationContext.setEquivalentDiscriminatedStrategy`. |
| `ExecutionStrategy.java` | Two-constant enum picking the executor's loop nesting. Exports `ELEMENT_BY_ELEMENT` (Zeta default — outer loop over source elements, inner over matching eager rules; a rule sees another rule's output only through the `equivalent()` cache) and `RULE_BY_RULE` (ETL-compatible — outer loop over rules in REGISTRATION order, inner over all matching elements, so a later rule sees every output of earlier rules). Both support parallel execution. Migrated ETL scripts that rely on cross-rule visibility need `RULE_BY_RULE`; under it, reordering rule methods in the source class changes results. Set via `TransformationExecutor.Builder.executionStrategy`. |
| `MultiSourceTransformFunction.java` | `@FunctionalInterface` a rule returns when it declares more than one `@Transform`. Exports `T transform(EObject[] sources, TransformationContext context)`. The `sources` array positions match `@Transform` declaration order, and the executor feeds it the Cartesian product of the aliased element collections — a two-source rule over 3×2 elements fires 6 times. Use `TransformFunction` for the single-source case; declaring multiple `@Transform` while returning `TransformFunction` mismatches the registry's expected shape. |
| `MultiSourceTransformGuard.java` | `@FunctionalInterface` guard for a multi-source rule. Exports `boolean evaluate(EObject[] sources, TransformationContext context)`. `false` skips that source combination entirely and the pair is memoised as rejected. Array order matches `@Transform` declaration order, same as `MultiSourceTransformFunction`. `TransformRuleDescriptor` picks this shape over `TransformGuard` by inspecting the guard method — a multi-source rule guarded with a single-source signature will not bind. |
| `OriginalTracker.java` | Records, per `(source identity, rule name)`, which `equivalentDiscriminated` caller arrived first and what base XMI id it claimed — the bookkeeping `CLONE_CURRENT_STATE` needs to hand the original to caller one and clones to the rest. Exports `record FirstCallResult(boolean isFirstCall, String firstDiscriminator)`, `checkAndRegisterFirstCall(EObject, String ruleName, String discriminator)`, `registerBaseId(...)`, `getBaseId(...)`, `clear()`. Keyed by `System.identityHashCode(source)` in a package-private `record OriginalKey`, so equal-but-distinct sources are distinct keys and a recycled identity hash could collide. Both registries use `putIfAbsent` — first write wins and re-registering a base id is a silent no-op. Backed by `ConcurrentHashMap`; `clear()` must run between transformations or first-call state leaks. |
| `RuleInheritanceGraph.java` | Builds the `@Extends` DAG and yields a parents-before-children execution order. Exports `addRule(TransformRuleDescriptor)`, `buildExecutionOrder()`, `validateGraph()`, `getExecutionOrder()`, `getParentRules(String)`, `getChildRules(String)`, `getRule(String)`, `getAllRules()`. `validateGraph()` throws `IllegalStateException` when a rule extends a non-existent parent, and again — naming the full path — on a cycle; an `@Abstract` rule with no children only WARNs. `getExecutionOrder()` lazily calls `buildExecutionOrder()` when it was never called, so validation can fire from a getter. Add every rule before building; `addRule` after a build leaves `executionOrder` stale. Backing maps are plain `HashMap` — single-threaded construction only. |
| `RuleInvocation.java` | Immutable `record` frame of the rule call stack, the input a `DiscriminatorResolver` inspects to see how a rule was reached. Exports components `ruleName()`, `source()`, `discriminator()`, factories `of(String, EObject)` (null discriminator) and `of(String, EObject, String)`, and a `toString` rendering `Name (source=EClassName) [disc=…]`. Chains are handed out most-recent-first by `TransformationContext.getRuleInvocationChain()`. Being a record, equality is component-wise and `source` compares by `EObject.equals` — not identity. |
| `ToDefinition.java` | Immutable value of one `@To`: which aliased resource a target type is created in. Exports ctor `(String alias, Class<? extends EObject> type)`, `getAlias()`, `getType()`, `equals`, `hashCode`, `toString` (renders `alias!TypeName`, the ETL notation). `final` class; ctor rejects a null alias or type with `NullPointerException` — the registry defaults the alias to `"target"` before constructing, never passes null. `TransformationContext.create(Type.class)` finds the alias by matching `getType()`, so two `ToDefinition`s with the same type and different aliases make target placement ambiguous. |
| `TransformDefinition.java` | Immutable value of one `@Transform`: which aliased resource a source type is read from. Exports ctor `(String alias, Class<? extends EObject> type)`, `getAlias()`, `getType()`, `equals`, `hashCode`, `toString` (`alias!TypeName`). `final`; ctor rejects null alias or type with `NullPointerException` — registry substitutes `"source"` first. Structurally identical to `ToDefinition` but NOT interchangeable: the executor reads element collections from these and creates into `ToDefinition`s. Count of these on a rule is what makes it multi-source. |
| `TransformFunction.java` | `@FunctionalInterface` every single-source `@TransformRule` method returns. Exports `T transform(S source, TransformationContext context)`, generic in `S extends EObject`, `T extends EObject`. The annotated method returns this lambda rather than performing the transform; `TransformRuleDescriptor.getFunction()` invokes the method once and caches the lambda, so the method body must be cheap and side-effect-free. Returning `null` from `transform` means "produced no target" and is a legitimate outcome, not an error. |
| `TransformGuard.java` | `@FunctionalInterface` guard for a single-source rule. Exports `boolean evaluate(EObject source, TransformationContext context)`. `false` skips the rule for that element; the `(source, rule)` pair is then memoised as rejected in `ElementResolutionCache`, so the guard is NOT re-evaluated even if the model later changes — call `clearRejections()` if it must be. Guard results are additionally memoised per `(guardMethod, source)` via `TransformationContext.putGuardResult`. |
| `TransformRuleDescriptor.java` | Registry's runtime record of one transformation rule and the entry point that executes it, including `@Extends` chaining. Exports `getName`, `getDescription`, `getSourceType`, `getTargetType`, `isLazy`, `isAbstract`, `isPrimary`, `isGreedy`, `isDetached`, `isActivityBased`, `isEagerExecutable`, `getOrdinal`/`setOrdinal`/`hasOrdinal`, `getExtendsRules`, `getTransforms`, `getTos`, `isMultiSource`, `getSourceCount`, `appliesTo(EObject)`, `evaluateGuard`, `getFunction`, `getMultiSourceFunction`, `getGuard`, `getMultiSourceGuard`, `execute(EObject, TransformationContext)`, `toString`, plus a 12-arg legacy ctor delegating to the 17-arg full form. `appliesTo` implements the `@Greedy` split: greedy → `sourceType.isInstance(source)` (kind-of); non-greedy → for an INTERFACE source type, `sourceType.getSimpleName().equals(source.eClass().getName())` (EMF type-name match, NOT Java `instanceof`), for a concrete class, exact `sourceType.equals(source.getClass())`. That name-based match means renaming an EClass silently unmatches the rule. `isEagerExecutable` is precomputed at construction as `!isLazy && !isMultiSource && !isAbstract`. `ordinal` starts at `-1`, is assigned once by `TransformationRegistry.register`, and backs O(1) array-indexed cache lookups — a descriptor built outside the registry has no ordinal and breaks in-progress tracking. `execute` saves/restores `currentExecutingRule`, `currentSource`, and inheritance state, pushes/pops a `RuleInvocation`, and enforces ETL's inheritance guard rule: EVERY parent rule's guard must pass or the whole chain aborts returning `null`. Function/guard lambdas memoise into non-volatile fields. |
| `TransformationContext.java` | The runtime object every rule body receives — 4900 lines and the module's true API surface. Ctor `(ModelProvider, ResourceSet source, ResourceSet target, ExtensionMethodRegistry)` pre-registers aliases `"source"` and `"target"` plus a reverse `ResourceSet`→alias index. Resolution: `equivalent(source, targetType)` / `(source, targetType, ruleName)` / `(source, ruleName)`, `equivalents`, `equivalentCached`, `equivalentDiscriminated`, `executeParentRule`, `findCachedTargetByName`. Creation: `createTarget` (4 overloads: type, type+`EPackage`, type+custom id, type+source+suffix), `create`, `buildSourceBasedId`, `addToResource`, `setElementId`/`getElementId`/`applyAllPendingXmiIds`. Model access: `all(alias, type)`, `getAllSource`, `registerResource`, `getResource`, `setPreferredSourceAlias`, `registerTargetPackage`/`getTargetPackages`/`setTargetPackage`. Config toggles: `setAutoAddRootElements`, `setUseStructuredIds`, `setIncludeElementNameInStructuredIds`, `setGlobalIdPrefix`, `setEtlCompatibilityMode`, `setEquivalentDiscriminatedStrategy`, `configureSequentialMode`. Call chain: `getRuleInvocationChain`, `getRuleInvocationDepth`, `isInRuleContext`, `findRuleInChain`, `formatRuleInvocationChain`, `setDiscriminatorResolver`. Deferred/parallel machinery: `enableDeferredWrites`/`disable`/`isDeferredWritesEnabled`, `getOperationQueue`, `commitDeferredOperations`, `commitDeferredOperationsIncremental`, `clearDeferredOperations`, `resetDeferredWrites`, `getPendingOperationCount`, `enableDeferredContainment`/`disable`, `queueContainmentOp`, `nextContainmentOpSequence`, `commitContainmentOps`, `unwrapProxy`, `unwrapAllProxiesInModel`, `isStagingEnabled`, `getStagedElementCount`, `getResourceLock`. Plus `activate`/`getActivationTracker`, `call(...)` extension dispatch, `setAttribute`/`getAttribute`, `getGuardResult`/`putGuardResult`/`clearGuardResultCache`, `clearExtensionCache`. Contracts: `currentSource` is a `ThreadLocal`, so `createTarget`'s source-derived ids only work on the thread executing the rule; the default `ElementResolutionCache` is PARALLEL mode and `configureSequentialMode` rebuilds it — the rebuild discards existing mappings, so call it before any transformation, not between passes; `setAttribute` wraps values in `Optional` so nulls are storable; deferred writes MUST be committed (`commitDeferredOperations`) or queued EMF containment writes never land; targets created under deferred mode are `DeferredEObject` proxies and must be unwrapped before serialisation. |
| `TransformationException.java` | `RuntimeException` carrying which rule and which element failed. Exports four ctors — `(String)`, `(String, Throwable)`, `(String, EObject, String ruleName)`, `(String, Throwable, EObject, String ruleName)` — plus `getFailedElement()`, `getRuleName()`, `toString()` appending `[rule: …] [element: EClassName]`. `failedElement` is `transient`, so it does NOT survive serialisation and is null after a round trip; `serialVersionUID = 1L`. The two short ctors leave both fields null — prefer the element-carrying forms so executor diagnostics can attribute the failure. |
| `TransformationExecutor.java` | Drives a transformation run: two-phase eager/lazy execution, multi-source Cartesian expansion, parallel chunking, fail-fast. Exports `builder()` and nested `Builder` (`registry`, `context`, `parallel`, `parallelThreshold`, `chunkSize`, `etlCompatibilityMode`, `executionStrategy`, `build`), `transform()`, `transform(Collection<? extends EObject>)`, `shutdown()`, plus a `@Deprecated` 3-arg ctor. Phase 1 runs non-lazy non-abstract rules; phase 2 runs lazy rules on demand from `equivalent()`. `DEFAULT_PARALLEL_THRESHOLD` is 1000 (note: validation's threshold is 5000 — they are different numbers) and default chunk size 100. Multi-source rules fire once per element combination, so a 3-source rule over large collections explodes multiplicatively. `etlCompatibilityMode(true)` applies activity-based processing to ALL `@Greedy @Lazy` rules without per-rule `@ActivityBased`. The activity-based fixpoint loop is capped at `MAX_ACTIVITY_BASED_ITERATIONS` = 100 to stop rules mutually re-activating forever. Errors publish into an `AtomicReference firstError` reset per `transform()` call — the first failure wins and the rest are dropped. `elementsByAliasAndType` memoises model traversal per `(alias, type)` so N rules sharing a type traverse once; it is cleared at end of run to avoid leaking the model. Ctor requires non-null registry and context (`Objects.requireNonNull`). `shutdown()` must be called or the executor service leaks. |
| `TransformationMetrics.java` | Global profiling counters for transformation hot paths. Exports `enable()`, `disable()`, `isEnabled()`, `reset()`, `getReport()`, getters (`getRuleIterations`, `getRuleExecutions`, `getGuardEvaluations`, `getEquivalentCalls`, `getEquivalentCacheHits`/`Misses`, `getGuardCacheHits`/`Misses`) and ~30 `record*` mutators (`recordEquivalentCall`, `recordGuardEvaluation`, `recordRuleExecution`, `recordFindByXmiIdScan`, `recordLockAcquisition`, `recordCreateTarget`, `recordExtensionMethodCall`, `recordAttributeSet`/`recordReferenceSet`, `recordEquivalentDiscriminatedCall`, `recordPostProcessingCall`, `startTransformation`/`endTransformation`, `addEquivalentNanos`, `addGuardEvaluationNanos`, `addRuleExecutionNanos`, `addGetRulesForSourceNanos`, `recordGreedyRuleExecution`, …). ALL STATE IS STATIC — counters are process-global `AtomicLong`s plus per-rule and per-extension-method `ConcurrentHashMap`s, so concurrent transformations in one JVM share and pollute them and tests must `reset()`. `enabled` is a `volatile boolean` defaulting to FALSE; every `record*` is inert until `enable()` is called, which is why leaving instrumentation calls in hot paths is cheap. Timings are nanosecond deltas — never wall-clock. |
| `TransformationRegistry.java` | Reflects annotated transformation classes into descriptors and owns every lookup index the executor uses. Exports `register(Class<?>)`, `getRulesForSource(Class)`, `getEagerRulesForType(Class)`, `getLazyRulesForType(Class)`, `getRuleByName(String)`, `getPrimaryRuleForTargetType(Class)`, `getAllRules()`, `getOrderedEagerRules()`, `getRuleCount()`, `invokePreTransformationHooks(TransformationContext)`, `invokePostTransformationHooks(TransformationContext)`. `register` WARNs and returns silently when the class lacks `@TransformationContext` — a mis-annotated class contributes no rules and does not fail; it instantiates via the no-arg declared constructor, scans declared methods for `@TransformRule` plus `@PreExecution`/`@PostExecution` hooks, and assigns each descriptor a sequential `nextOrdinal`. Primary maps are `LinkedHashMap` precisely to preserve REGISTRATION order — `getOrderedEagerRules()` (the `RULE_BY_RULE` execution order) is that order, so moving a rule method changes behaviour under that strategy. Derived indexes (`rulesBySourceTypeCache`, `eagerRulesByTypeCache`, `lazyRulesByTypeCache`, `primaryRuleByTargetTypeCache`) are `ConcurrentHashMap`s safe for parallel reads, and `orderedEagerRulesCache` is `volatile`; but the primary `LinkedHashMap`s are not synchronised, so register everything before transforming and never register concurrently or mid-run. |
| `TransformationResult.java` | Thin return value of `TransformationExecutor.transform()`. Exports ctor `(TransformationContext, long durationMs)`, `getTargetResourceSet()`, `getContext()`, `getDurationMs()`, `getTrace()`. Holds no results of its own — everything delegates to the live `TransformationContext`, so mutating the context after the run changes what the result reports. `getTrace()` constructs a FRESH `TransformationTrace` over the context's `ElementResolutionCache` on every call; calling it after the cache is cleared yields an empty trace. |
| `TransformationTrace.java` | Serialises the source→target mapping trace to JSON for debugging and ETL-vs-Zeta diffing. Exports ctor `(ElementResolutionCache)`, `getEntries()`, `saveToJson(File)` (UTF-8, buffered), `saveToJson(Writer)`, `toJson()`. Emits `{traceEntries, entryCount, timestamp}` via pretty-printing Gson; each entry carries `ruleName`, `source`/`target` info (`type`, `id`, optional `name` read from an EMF `name` feature), `primary`, and `discriminator` when non-null. Element id resolution falls back in order: `Resource.getURIFragment` when it is NOT a `/`-prefixed positional fragment, then an EMF `id` feature, then `obj@<identityHashCode>` — that last form is per-JVM-run and makes traces non-comparable across runs. The view is LIVE over the cache, not a snapshot; clearing the cache empties it. |
